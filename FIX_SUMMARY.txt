💡 WHAT WAS WRONG
────────────────────────────────────────────────────────────────────────────

When the LLM returned a None or incomplete JSON response for intent parsing,
the system tried to:

  1. Apply a regex to None → TypeError
  2. This exception wasn't caught → Unhandled crash
  3. Code tried to call .get() on a None object → AttributeError
  4. USER SEES: "intent_parsing_error" + complete workflow failure


✅ WHAT WAS FIXED
────────────────────────────────────────────────────────────────────────────

THREE layers of protection added:

  1️⃣  SAFETY CHECK (Early Prevention)
      ├─ Detect None/non-string responses immediately
      ├─ Log diagnostic info
      └─ Return safe default without crashing

  2️⃣  EXPANDED EXCEPTION HANDLING
      ├─ Catches TypeError (new!)
      ├─ Catches ValueError (new!)
      └─ Already caught JSONDecodeError & AttributeError

  3️⃣  MULTI-LEVEL FALLBACK
      ├─ Try structured parsing first
      ├─ If that fails, try simple parsing
      └─ If that fails, return guaranteed-safe dict
