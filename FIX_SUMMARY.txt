PROBLEM FIXED:
  The discovery agent was generating SQL with non-existent column names
  Example: SELECT TOP 5 * FROM dbo.KHKAdressen ORDER BY [Name]
  Error: "Ungültiger Spaltenname 'Name'" (Invalid column name)

ROOT CAUSE:
  LLM was too creative, guessing column names instead of using only columns
  from the schema provided

SOLUTION IMPLEMENTED:
  Two-layer validation system:
  
  Layer 1: Stricter LLM Prompt (PREVENTIVE)
  - File: langgraph_integration/prompts/__init__.py (SQL_GENERATOR_PROMPT)
  - Added explicit warnings against column hallucination
  - LLM now told to use SELECT * if unsure about column names
  
  Layer 2: Post-Validation (DEFENSIVE)  
  - File: langgraph_integration/graph_definition.py
  - New method: _validate_sql_columns() → Checks columns exist in schema
  - New method: _extract_primary_table() → Gets table name for fallback
  - If validation fails: Automatic fallback to SELECT TOP 100 * FROM {table}

HOW IT WORKS:

  1. User asks query
  2. LLM generates SQL (with improved prompt)
  3. Validation checks: Are all [bracketed] columns in schema?
  4. If Yes: Execute as-is
  5. If No: Extract table name, use fallback SELECT *
