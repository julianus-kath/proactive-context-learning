ISSUE FIXED:
  ❌ Web UI: "how many customers?" → Asks for clarification, can't find table
  ✅ Direct API: "how many customers?" → Returns actual customer count from MSSQL
  
ROOT CAUSE:
  1. Two orchestration systems existed (confusion)
  2. Intent parser tried to find tables instead of letting Scout search find them
  3. When intent parser couldn't find table in schema, it returned "clarify"
  4. This prevented the downstream table discovery mechanism from running

SOLUTION:
  1. Archived dead code: orchestrator.py → /archive/orchestrator_deprecated/
  2. Fixed intent parser: Now ALWAYS returns operation="query" (never "clarify")
  3. Updated router: All queries now go through select_tables for table discovery
  4. Result: One unified system, clear separation of concerns
