# H2a Benchmark Extension Report — German L1-L2 Cohort

**Date:** 2026-04-18
**Scope:** Appendix to the canonical H2a evaluation. Adds 20 German L1-L2 queries to the existing 64-query Northwind benchmark to decouple the language axis from the difficulty axis at the low-difficulty edge. **Total benchmark size after extension: N=84.**
**Author:** Julianus Kath (study design and German translations); automated pipeline (runs, labelling, statistics).

> **Terminology.** The thesis reports a single ablation: **SDG-off vs SDG-on**. The toggle is whether the Scout catalog loads `northwind_descriptions.json` at runtime (off → no descriptions; on → 14 LLM-generated table descriptions used by the ranker). Some artefact files generated by the framework before label normalisation use the legacy strings `scout_structural` (≡ SDG-off) and `scout_enriched_ranked` (≡ SDG-on). All numbers and tables in this report use the SDG-off / SDG-on labels.

### 1.2 Translation methodology

- **Calibration corpus.** Existing German queries CL1-CL12 (L3 crosslingual), HX1-HX12 (L4 complex), and the US_CL* (L5) paraphrases were used to calibrate register, terminology, and sentence structure.
- **Register.** Standard written German appropriate for Swiss business reporting. Thousands separator `'` (Swiss) applied in any numeric mention. Informal phrasing avoided.
- **Lexical mismatch.** Every German query uses business vocabulary with zero lexical overlap with the English-named Northwind schema — `Artikel` not `products`, `Abnehmer` not `customers`, `Meldebestand` not `reorder_level`, `Auftragsnummer` not `order_id`, `Versanddienstleister` not `shippers`, `rabattiert` not `discount`, `Nettoumsatz` not `revenue`. This is the vocabulary-gap condition the extension is designed to probe.
- **Ground truth.** German prompts preserve the English intent exactly, so the reference SQL is copied verbatim. Any metric delta between the English and German cohorts is attributable to language alone.
- **No machine translation.** All 20 queries were authored directly, calibrated against the existing German-language corpus in the dataset.

### 1.3 Run configuration

Both runs use the H2a pipeline `code/eval/run_h2a_full_pipeline.py`, temperature 0, `gpt-4o-mini`, matching the April 14 configuration. The only variable changed between the two runs is the SDG toggle:

| | SDG-off | SDG-on |
|---|---|---|
| `SCOUT_DESCRIPTIONS_ENABLED` | `false` | `true` |
| `SCOUT_DESCRIPTIONS_RANKING` | `false` | `true` |
| `SCOUT_DESCRIPTIONS_CACHE_PATH` | n/a | `eval/cache/northwind_descriptions.json` |
| SDG enrichment observed at startup | `writes=14 non_empty=0/14` | `writes=14 non_empty=14/14` |

**Cross-snapshot caveat.** The April 14 runs were executed against the `gpt-4o-mini` snapshot current on 2026-04-14. The April 18 runs use the snapshot current on 2026-04-18. OpenAI does not pin snapshots; any silent model drift between the two dates is a within-study methodological caveat. The extension exercises only the 20 new queries and uses the April 18 snapshot uniformly for both conditions of the delta cohort, so the condition contrast on the delta cohort itself is not confounded by drift.

## 2. Quality check — three randomly sampled queries

The following three new queries were sampled for spot-checking (seeded: `NW_DE_04`, `NL_DE_05`, `NW_DE_09`). Full reference rowsets are in `code/eval/runs/20260418_*_semantic_labels/reference_results.jsonl`.

### `NW_DE_04` — late shipments per shipper (L1 direct)
- Reference SQL (copied from NW4):
  ```sql
  SELECT s.shipper_id, s.company_name,
         COUNT(*) FILTER (WHERE o.shipped_date > o.required_date) AS late_shipments,
         COUNT(*) AS total_shipments
  FROM public.shippers s
  JOIN public.orders o ON o.ship_via = s.shipper_id
  GROUP BY s.shipper_id, s.company_name
  ORDER BY s.shipper_id
  ```
- Reference rowset head: `(1, 'Speedy Express', 12, 249)` — 3 rows total.

### `NL_DE_05` — highest avg basket by buyer location (L2 paraphrase)
- Reference SQL (copied from NL5): two-step CTE computing per-order total then averaging per `c.country`.
- Reference rowset head: `('Austria', 3200.10)` — 21 rows total.

### `NW_DE_09` — pending orders scalar aggregate (L1 direct)
- Reference SQL (copied from NW9): `COUNT(DISTINCT o.order_id), SUM(unit_price*quantity*(1-discount))` with `WHERE o.shipped_date IS NULL`.
- Reference rowset: single row `(21, 25937.43)`.

All three reference SQLs executed cleanly in `<10 ms` each under the same 15 s statement-timeout budget used by the canonical labeller. A full smoke-test over all 20 reference SQLs (run pre-append) showed 20/20 clean execution.

## 3. Delta-only results (new cohort, n=20)

### 3.1 Table recall

| Condition | Mean recall | SD | SQL-generation rate | Perfect recall | Zero recall |
|---|---|---|---|---|---|
| SDG-off | **0.7083** | 0.4194 | 80.00 % | 11 / 20 | 4 / 20 |
| SDG-on | **0.8417** | 0.3486 | 90.00 % | 15 / 20 | 2 / 20 |
| Δ (on − off) | **+0.1333** | — | +10.00 pp | +4 | −2 |

### 3.2 Per-level breakdown (delta cohort)

| Level | n | SDG-off mean | SDG-on mean | Δ |
|---|---|---|---|---|
| L1_DE (direct) | 10 | 0.8667 | 0.9667 | +0.1000 |
| L2_DE (paraphrase) | 10 | 0.5500 | 0.7167 | +0.1667 |

### 3.3 Semantic labels on the delta cohort

| | CORRECT | PARTIAL | INCORRECT | ERROR | Acceptable (C+P) |
|---|---|---|---|---|---|
| SDG-off | 10 | 3 | 7 | 0 | 65.00 % |
| SDG-on | 10 | 4 | 6 | 0 | 70.00 % |
| Δ | 0 | +1 | −1 | 0 | **+5.00 pp** |

Per-level semantic labels (SDG-off → SDG-on):

- L1_DE: `9 C / 0 P / 1 I` → `10 C / 0 P / 0 I` (full clearance at L1 under SDG-on).
- L2_DE: `1 C / 3 P / 6 I` → `0 C / 4 P / 6 I` (gain is in paraphrase cases the agent now attempts with a non-empty rowset, but the rowset does not yet match reference exactly).

The gap between recall improvement (+13.3 pp) and semantic-accuracy improvement (+5 pp) is concentrated in L2 paraphrases where SDG lets the agent reach the correct tables but the generated SQL still differs from the reference (projection, GROUP BY key, or LIMIT choices). This is the same pattern observed on the canonical 64-query cohort in the April 16 labelling run.

### 3.4 Paired Wilcoxon (delta cohort)

One-sided Wilcoxon signed-rank test, alternative `SDG-on > SDG-off`, on per-query paired recall values:

- W = 10.0, p = 0.0625 (one-sided)
- Wins SDG-on = 4 · Wins SDG-off = 0 · Ties = 16
- Rank-biserial proxy = 1.000 (all non-zero differences favour SDG-on)

The delta-cohort test is **directionally consistent but underpowered** — 16 of 20 pairs produced identical recall under both conditions (mostly L1_DE perfect-recall ties). The combined N=84 test in §4 is the properly-powered version.

### 4.4 Paired Wilcoxon (N=84)

One-sided Wilcoxon signed-rank test, alternative `SDG-on > SDG-off`, on per-query paired recall values:

- **W = 163.5, p = 0.00026 (one-sided)**
- Wins SDG-on = 17 · Wins SDG-off = 1 · Ties = 66
- Rank-biserial proxy = 0.889

The combined test rejects the null of no improvement at any conventional α. SDG-on strictly improves per-query recall on 17 queries and reduces it on 1, with the remaining 66 tied (mostly L1_EN, L2_EN, and perfect-recall L1_DE).

### 4.5 Sensitivity check — queries where both conditions produced SQL

Restricting to the 58 of 84 queries where both conditions generated non-empty SQL:

- SDG-off mean recall = 0.8626
- SDG-on mean recall = 0.8986
- Δ = +0.0359
- Wilcoxon: W = 21.0, p = 0.016 (one-sided), wins_on / wins_off / ties = 8 / 1 / 49

The sensitivity check confirms that the SDG lift is not driven only by turning non-answers into answers. Even on the subset where the agent produced SQL under both conditions, SDG-on retrieves the correct tables more often (p = 0.016). The larger overall lift (+14.4 pp) therefore reflects both the "more-SQL" effect (SDG-off fails to generate SQL on 16 queries, SDG-on on 10) and a within-SQL improvement in table selection (+3.6 pp on the both-SQL subset).

## 5. Plain-language interpretation

The extension breaks the language-by-difficulty confound at the low-difficulty edge of the benchmark. On 20 newly authored German L1-L2 queries — where difficulty is not at ceiling but the vocabulary gap to the English-named schema is at its smallest — SDG raises mean recall from 0.708 to 0.842 (+13.3 pp) and semantic-acceptance from 65 % to 70 %. Both L1_DE (+10 pp) and L2_DE (+16.7 pp) benefit, while the English L1_EN and L2_EN cohorts remain at ceiling. The combined N=84 Wilcoxon test rejects the null of no improvement at p = 0.00026. This refines the thesis claim: the vocabulary-gap mechanism activates whenever the natural-language query uses terminology that is lexically unrelated to the schema, regardless of query difficulty. The extension closes the examiner-flagged confound and makes the per-language breakdown defensible.
